# راهنمای فارسی وی‌سی‌ان‌پی (VCNP Vibe-Office)

> دفتر مجازیِ عامل‌های هوش مصنوعی — برای کسانی که می‌خواهند یک «شرکتِ کوچک از ایجنت‌ها» را اداره کنند، بدون اینکه اصلاً برنامه‌نویس باشند.
>
> 🇬🇧 Developers and contributors: see the English [README](README.md) for architecture details, folder map and MCP tool reference.

---

## 🪟 این چیست؟

**وی‌سی‌ان‌پی وایب‌آفیس** یک کیت آماده است که به شما کمک می‌کند پروژه‌هایتان را مثل یک مدیرعامل جلو ببرید:

- شما با یک «مدیرعامل هوش مصنوعی» (مدل `vcnp-ceo`) صحبت می‌کنید و هدف‌تان را می‌گویید.
- مدیرعامل، کار را بین ۸ همکار دیگر تقسیم می‌کند: برنامه‌ریز، هماهنگ‌کننده، مجری، کنترل کیفیت، امنیت، کنترل منابع، کتابدار و دواپس.
- همهٔ این‌ها روی یک **دفتر مشترک** کار می‌کنند: یک دفترچهٔ رویداد (`office/events.log.jsonl`) که منبع حقیقت است؛ تختهٔ کانبان، داشبورد و گزارش‌ها همه از روی آن ساخته می‌شوند.
- هیچ چیزی ابری نیست؛ همه‌چیز روی کامپیوتر خودتان و داخل پوشهٔ `office/` همان پروژه ذخیره می‌شود.

نتیجه: یک دیوار زندهٔ پیکسلی دارید که کارمندانِ هوش مصنوعی‌اش واقعاً بر اساس رویدادهای پروژه حرکت می‌کنند — نه انیمیشن تزئینی.

## 🚀 شروع سریع

### پیش‌نیازها

| نیاز | توضیح |
|---|---|
| **Node.js نسخهٔ ۲۰ یا بالاتر** | از [nodejs.org](https://nodejs.org) نسخهٔ **LTS** را نصب کنید. بررسی: در ترمینال بنویسید `node --version` |
| **کلید API یا Ollama** | برای قابلیت دسته‌ای `llm_batch` یکی از این دو لازم است: ۱) یک کلید API (مثلاً OpenRouter) که به‌صورت متغیر محیطی تنظیم شود، یا ۲) [Ollama](https://ollama.com) روی همین سیستم — که **بدون هیچ کلیدی** کار می‌کند |

> صادقانه بگوییم: اگر نه کلید API داشته باشید و نه Ollama، باز هم تقریباً همه‌چیز کار می‌کند (تخته، گیت‌ها، گزارش‌ها، داشبورد). فقط کارهای دسته‌ایِ LLM با پیام «no provider configured» تمام می‌شوند — یعنی سیستم به‌جای دروغ‌گفتن، شکست را گزارش می‌کند.

### نصب با یک دستور

این پوشهٔ کیت را باز کنید و بسته به سیستم‌عامل:

**ویندوز (PowerShell):**

```powershell
powershell -ExecutionPolicy Bypass -File installer\install.ps1 -Target "C:\مسیر\پروژهٔ-شما"
```

**مک / لینوکس / Git Bash:**

```bash
bash installer/install.sh /path/to/project
```

اگر مسیر ندهید، همان پوشهٔ فعلی نصب می‌شود. نصاب چه‌کار می‌کند؟

1. وجود Node.js ≥ ۲۰ را بررسی می‌کند (اگر نباشد، پیام دوزبانهٔ راهنما می‌دهد).
2. داخل پروژهٔ مقصد، پوشهٔ `office/` را **فقط اگر وجود نداشته باشد** می‌سازد (هرگز فایل موجود را بازنویسی نمی‌کند).
3. سرور MCP دفتر را با نام `vcnp-office` در فایل `.mcp.json` پروژه ثبت می‌کند — بقیهٔ ورودی‌های آن فایل دست‌نخورده می‌مانند.
4. یک نسخهٔ داشبورد به‌عنوان جایگزین در `office/dashboard.html` می‌گذارد.

> 💡 حذف نصب هم همین‌قدر ساده است: `installer\uninstall.ps1` یا `bash installer/uninstall.sh`. داده‌های `office/` به‌طور پیش‌فرض **حفظ می‌شوند**؛ فقط با پرچم `-DeleteOffice` / `--delete-office` حذف می‌شوند.

## 👔 اولین پروژه با مدیر کل

۱. پوشهٔ پروژهٔ مقصد را در **VS Code + RooCode** باز کنید.
۲. از انتخاب‌گر حالت (پایین چت)، حالت **`vcnp-ceo`** را برگزینید.
۳. مثل صحبت با یک مدیرعامل واقعی، هدفتان را بگویید. نمونهٔ یک گفتگو:

> **شما:** می‌خواهم یک سایت معرفی برای کافه‌ام بسازم؛ یک صفحه با منو، ساعت کاری و شماره تماس.
>
> **مدیرعامل (vcnp-ceo):** هدف ثبت شد. سه تسک تعریف کردم:
> T-001 بخش قهرمان (hero) با نام کافه — سپرده به «مجری»
> T-002 جدول منو با ۶ آیتم — سپرده به «مجری»
> T-003 فوتر با ساعت کاری و تلفن — سپرده به «مجری»
> معیارهای پذیرش هر تسک روی تخته ثبت شد و بودجهٔ توکن هرکدام مشخص است.
>
> **شما:** ادامه بده.
>
> **مدیرعامل:** T-001 انجام و توسط QA تأیید شد ✅ — T-002 در حال ساخت…

۴. هر وقت خواستید وضعیت را ببینید، از مدیرعامل بخواهید `report_generate` را اجرا کند تا تخته و داده‌های داشبورد تازه شوند.

## 🖥️ دیوار زنده

فایل **`office/dashboard.html`** را در مرورگر باز کنید (دابل‌کلیک کافی است — نیازی به سرور نیست):

- صحنهٔ پیکسلی دفتر با ۹ کارمند؛ حال‌وهوای هرکدام (در حال کار، فکر کردن، قهوه، جلسه، خواب) از **رویدادهای واقعی** دفتر ساخته می‌شود.
- اتاق جلسه در مرکز، تیکر زنده روی نمایشگر دیواری، نوار انرژی زیر پای هر کارمند.
- روز و شبِ صحنه از ساعت واقعی سیستم پیروی می‌کند.
- **رفرش برای دادهٔ تازه:** دکمهٔ «↻ بازخوانی داده» را بزنید یا صفحه را دوباره باز کنید. داده‌ها از فایل `office/dashboard-data.js` می‌آیند که با ابزار MCP به نام `report_generate` ساخته می‌شود.
- تا وقتی هنوز هیچ گزارشی ساخته نشده، دیوار صادقانه می‌گوید: «چراغ‌ها روشن است، اما داده‌ای نرسیده».

## ☎️ تلفنخانه — گفتگوی زنده و تماس صوتی

علاوه بر داشبورد ثابتِ فایلی، یک **دفتر زنده** هم وجود دارد که همان دفترچهٔ رویداد را از راه یک سرور محلی به‌روزرسانی آنی می‌دهد.

### راه‌اندازی

```bash
cd mcp/vcnp-office-mcp
npm run live
```

سرور روی `http://127.0.0.1:7788` بالا می‌آید (فقط روی همین کامپیوتر، قابل تغییر با متغیر محیطی `VCNP_OFFICE_PORT`). حالا فایل `office/live/index.html` را در مرورگر باز کنید:

- با `?style=pixel` سبک پیکسلی و با `?style=studio` سبک استودیوی ایزومتریک را می‌بینید؛ انتخاب شما در مرورگر ذخیره می‌شود.
- دیگر نیازی به دکمهٔ «بازخوانی» نیست — صفحه با اتصال زنده (SSE) خودش تازه می‌شود؛ اگر سرور خاموش باشد، به‌طور صادقانه به همان اسنپ‌شات فایلی برمی‌گردد و برچسب «آفلاین» را نشان می‌دهد.

### گفتگو با مدیرعامل

از داخل صفحهٔ زنده می‌توانید برای هر نقش پیام تایپ کنید. پیام روی دفتر رویداد ثبت می‌شود و در صف انتظار می‌ماند تا یک نشست واقعی `vcnp-ceo` آن را بخواند و جواب دهد — **هیچ پاسخ خودکار یا جعلی وجود ندارد**؛ تا وقتی کسی جواب ندهد، وضعیت صادقانه «در انتظار نشست» نمایش داده می‌شود.

از خط فرمان هم می‌توانید همان کار را انجام دهید (مثلاً برای اسکریپت یا تست):

```bash
node tools/phone-drop.js --text "وضعیت پروژه چیست؟" --to ceo
```

### تماس صوتی

دکمهٔ «☎ تماس با مدیر» در صفحهٔ زنده (فقط وقتی سرور روشن است — ضبط صدا روی `file://` مسدود است) صدای شما را ضبط و ارسال می‌کند؛ اگر تشخیص گفتار فارسی در دسترس باشد متن آن هم پیوست می‌شود، وگرنه صدا بدون متن با برچسب صادقانهٔ «بدون متن» ثبت می‌شود — هرگز متنی ساختگی جایگزین نمی‌شود.

برای ارسال یک فایل صوتی از خط فرمان:

```bash
node tools/phone-drop.js --audio C:\masir\yaddasht.webm --transcript "متن اختیاری" --lang fa-IR
```

هر دو راه (مرورگر و خط فرمان) یک مسیر نوشتاری یکسان دارند: فایل صدا در `office/phone/` ذخیره و دو رویداد (تماس + پیام) روی دفتر ثبت می‌شود؛ مدیرعامل همان‌طور که پیام‌های متنی را می‌خواند، این‌ها را هم از صندوق ورودی می‌خواند.

### اثبات سرتاسری

اگر می‌خواهید مطمئن شوید همه‌چیز واقعاً زنده کار می‌کند (نه فقط تئوری):

```bash
node demo/run-live-office.js
```

این اسکریپت سرور را روی یک پورت آزاد بالا می‌آورد، یک پیام وب و یک پیام از خط فرمان می‌فرستد، دریافت هر دو را از طریق همان اتصال SSE با چشم خودش می‌بیند، تازه‌بودن آینه‌های دیسک را چک می‌کند و فقط در صورتی با کد ۰ خارج می‌شود که همهٔ این مراحل واقعاً و بدون شبیه‌سازی تأیید شده باشند.

### درِ سوم: خط تلفن واقعی (مرکز تلفن ویپ)

اگر یک صندوق پیام صوتی واقعی روی یک مرکز تلفن (مثلاً یک داخلی Asterisk) دارید، `tools/voip-inbox-poll.js` آن را هر ۲۰ ثانیه می‌خواند و هر پیام تازه را از همان مسیر نوشتاریِ دو راه دیگر (ویجت مرورگر و `phone-drop.js`) به دفتر می‌فرستد — یعنی هر سه راه دقیقاً همان جفت رویداد را روی دفتر ثبت می‌کنند. چون ضبط تلفنی WAV هشت‌کیلوهرتزی است (نه فرمت فشردهٔ مرورگر)، اعتبارسنج‌های تلفنخانه از این پس `audio/wav` را هم می‌پذیرند.

```bash
export VOIP_INBOX_TOKEN='...'   # هرگز در گیت commit نکنید
node tools/voip-inbox-poll.js --health     # فقط تست اتصال
node tools/voip-inbox-poll.js              # اجرای دائمی
```

اگر سرویس راه دور هنوز رونویسی نکرده، `transcript` صادقانه `null` می‌ماند — دقیقاً مثل وقتی که تشخیص گفتار مرورگر شکست می‌خورد؛ هیچ‌وقت متنی ساختگی جایگزین نمی‌شود.

## ⚙️ اجرای سرور و تست‌ها

سرور MCP دفتر، بدون هیچ وابستگی npm و فقط با کتابخانه‌های خود Node نوشته شده:

```bash
cd mcp/vcnp-office-mcp
npm start        # node src/server.js — پروتکل JSON-RPC 2.0 روی stdio
npm test         # node test/smoke.js — تست دود سرتاسری (۲۲ بررسی)
```

ثبت در کلاینت MCP (نمونهٔ `.mcp.json`):

```json
{
  "mcpServers": {
    "vcnp-office": {
      "command": "node",
      "args": ["C:/absolute/path/to/this-kit/mcp/vcnp-office-mcp/src/server.js"]
    }
  }
}
```

همهٔ نوشتن‌ها محدود به پوشهٔ `office/` همان پروژه است.

## 🩹 عیب‌یابی — ۵ خطای رایج

۱. **«Node.js version 20 or newer is required…»**
   Node نصب نیست یا قدیمی است. از [nodejs.org](https://nodejs.org) نسخهٔ LTS را نصب کنید، ترمینال را ببندید و باز کنید، بعد نصاب را دوباره اجرا کنید.

۲. **«existing .mcp.json is not valid JSON – aborting to avoid data loss»**
   فایل `.mcp.json` پروژهٔ مقصد خراب است و نصاب عمداً به آن دست نمی‌زند. فایل را باز کنید، خطای JSON را پیدا کنید (معمولاً ویرگول اضافه) یا موقتاً تغییر نام دهید و دوباره نصب کنید.

۳. **داشبورد می‌گوید «داده‌ای نرسیده»**
   طبیعی است؛ دادهٔ داشبورد با پرچم خط فرمان ساخته نمی‌شود. از مدیرعامل بخواهید ابزار `report_generate` را یک بار اجرا کند، بعد صفحه را رفرش کنید.

۴. **ابزارهای `vcnp-office` در RooCode دیده نمی‌شوند**
   مسیر داخل `args` باید **مطلق** و درست باشد (نصاب خودش این‌کار را می‌کند). بعد از تغییر `.mcp.json`، یک بار VS Code را Reload Window کنید.

۵. **کارهای `llm_batch` با «no provider configured» تمام می‌شوند**
   یعنی نه کلید API تنظیم کرده‌اید و نه Ollama در دسترس است. متغیرهای محیطی (مثل `OPENROUTER_API_KEY`) یا آدرس Ollama را تنظیم کنید. توجه: این شکستِ صادقانه است، نه خرابی.

## ❓ پرسش‌های پرتکرار

**داده‌های من کجا ذخیره می‌شود؟**
فقط داخل پوشهٔ `office/` همان پروژه، روی کامپیوتر خودتان. هیچ چیزی به جایی ارسال نمی‌شود.

**بدون کلید API هم می‌توانم استفاده کنم؟**
بله. تخته، گیت‌ها، گزارش‌ها و داشبورد محلی‌اند. فقط `llm_batch` به یک ارائه‌دهنده (کلید API یا Ollama) نیاز دارد.

**اگر پوشهٔ `office/` را پاک کنم چه می‌شود؟**
حافظهٔ پروژه (رویدادها، تخته، بانک حافظه) از بین می‌رود. به همین دلیل حذف‌کننده بدون پرچم صریح (`-DeleteOffice` / `--delete-office`) هرگز آن را پاک نمی‌کند.

**هزینه و مصرف توکن کجا ثبت می‌شود؟**
در دفتر رویدادها با برچسب منبع (`provider_usage` / `ide_export` / `estimated`). اعداد تخمینی صادقانه «تخمینی» علامت می‌خورند و در سقف بودجه لحاظ نمی‌شوند.

**چند پروژه می‌توانم داشته باشم؟**
به تعداد دلخواه — هر پروژه `office/` مستقل خودش را دارد. کافی است نصاب را در پوشهٔ هر پروژه اجرا کنید.
