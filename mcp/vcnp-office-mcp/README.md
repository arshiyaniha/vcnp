# vcnp-office-mcp

The VCNP Vibe-Office shared-state MCP server (plan §6.2): board, event ledger,
model router, telemetry, `llm_batch`, reports and compaction gate.

**Node.js ≥ 20 · ZERO npm dependencies** — pure stdlib (`node:fs`, `node:crypto`,
`readline`). MCP protocol over **stdio**: newline-delimited JSON-RPC 2.0.

## Run

```bash
cd mcp/vcnp-office-mcp
npm start          # node src/server.js
npm test           # node test/smoke.js — end-to-end smoke test against a temp workspace
```

## Register in an MCP client

Add to your client's MCP config (e.g. `.mcp.json` at the workspace root):

```json
{
  "mcpServers": {
    "vcnp-office": {
      "command": "node",
      "args": ["mcp/vcnp-office-mcp/src/server.js"]
    }
  }
}
```

- Use an absolute path in `args` if your client launches processes from a
  different working directory.
- The workspace root (home of `office/`) is resolved automatically by walking up
  from `src/server.js`; override with the `VCNP_OFFICE_WORKSPACE` env var if needed:

```json
{
  "mcpServers": {
    "vcnp-office": {
      "command": "node",
      "args": ["mcp/vcnp-office-mcp/src/server.js"],
      "env": { "VCNP_OFFICE_WORKSPACE": "/absolute/path/to/workspace" }
    }
  }
}
```

## Tools (13)

| Tool | Purpose |
|---|---|
| `board_init(project_name, goal)` | Create/update the project header |
| `task_create(title, assignee_role, acceptance_criteria[], budget_tokens, task_class)` | Task Brief envelope; validated against `skills/core-protocol/references/envelope-schema.json` |
| `task_update(task_id, status?, progress_percent?, artifacts?, blockers?, notes_for_qa?, board_status?)` | Result Report envelope; validated; `status:"done"` moves the task to the `awaiting_orchestrator` written queue |
| `task_assign(task_id, role, session_id?)` | Assignment GATE: refuses until the target session has a `compaction_done` that is still the LATEST util-related event for that session |
| `board_read()` | Compact snapshot incl. the written queue |
| `ledger_log(role, task_id, tokens_used, source, ...)` | Token usage; `source ∈ provider_usage\|ide_export\|estimated` (`estimated` recorded but flagged «تخمینی», never budget-enforced) |
| `event_log(actor, action, detail?)` | Generic audit event |
| `telemetry_read()` | Per-role/per-model tokens, est cost, avg latency, QA approval counts |
| `route_model(task_class)` | Cheapest model whose quality_tier meets the class bar (C0/C1→1, C2→2, C3→3, C4→largest ctx); escalation/de-escalation counters per model+class |
| `llm_batch_submit(jobs[], model_class)` | Async bulk jobs; returns `batch_id` instantly |
| `llm_batch_status(batch_id)` | Batch/job states + failure reasons |
| `report_generate()` | Regenerates `office/BOARD.md` + `office/office-live.json` |
| `compaction_ack(session_id, util_after)` | Deterministic `compaction_done` writer (util_after ≤ 0.75 AND Memory Bank actually updated) |

> Naming note: the plan writes `llm_batch.submit/status`; MCP tool names disallow
> dots, so they are exposed as `llm_batch_submit` / `llm_batch_status`.

## Files written (all confined to `<workspace>/office/`)

| File | Role |
|---|---|
| `events.log.jsonl` | ⭐ SOURCE OF TRUTH — append-only ledger |
| `state.json` | Derived cache — temp file + atomic rename, never written in place |

## Provider configuration (llm_batch)

Optional `office/models.json` (see plan §7 for the full shape). Keys are referenced
by env-var NAME only — raw secrets live in `.env`, never in config:

```json
{
  "providers": [
    { "id": "openrouter", "base_url_env": "OPENROUTER_BASE_URL", "key_env": "OPENROUTER_API_KEY", "kind": "openai-compatible" },
    { "id": "local", "base_url_env": "OLLAMA_BASE_URL", "key_env": null, "kind": "openai-compatible" }
  ],
  "models": [
    { "id": "economy-fast", "provider": "openrouter", "model_ref": "...", "in_price": 0.05, "out_price": 0.2, "ctx": 128000, "quality_tier": 1 }
  ]
}
```

Without a reachable provider (env vars unset), `llm_batch_submit` still works —
every job completes honestly as failed with `"no provider configured"`.

## Honest limitations

- Envelope validation is a **lightweight approximation** of the JSON Schema
  (required fields / types / enums / minItems / the done→blockers if-then rule);
  full JSON-Schema evaluation would need a dependency, which the zero-dep
  constraint forbids.
- The batch worker lives inside this server process — batches die with it.
- `route_model` ADVISES mode selection only; it cannot change the calling
  session's model (plan §7 honesty layers).
- Cost figures for telemetry lines without an in/out token split use the midpoint
  of in/out prices and are labeled approximate.
